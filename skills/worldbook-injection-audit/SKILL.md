## 二、权威口径测量法

**不要**用"理论公式估算"交差。两级数据一起给：

1. **真实 token**：`D:\DSH\_agenttest\game\turns\turnNN.json` 的 `usage.prompt_tokens` / `prompt_cache_hit_tokens`。
   这是 API 返回的 ground truth。
2. **字符分解**：按层拆 desc / 常态 / 关键词命中 / 表头。

字符→token 换算：中文 ≈ **0.6 token/字**（DeepSeek 系）。
交叉校验：分解出的注入字符 × 0.6 ≈ `prompt_tokens − 历史对话`。若差出一份 desc 的量，说明 desc 被重复注入了（卡片 desc + persona prefix 同源时要注意）。

## 三、四类必查问题

### 1. 事实常态（最大陷阱）
触发词是"日常场景词/物体词/常见动词"→ 命中率 ≥50% → **等价于每轮都在**，但导出时看不出。
检出法：拿真实 20 轮做命中率统计，命中率 ≥50% 单独列一张表，按"每轮成本 = 字符 × 命中率"排序。
典型罪魁：`旅行 荒野 城市 城镇 酒馆`（遭遇表）、`名字 称呼`（名称库）、`买 商店 物品`（生成-物品）。

### 2. first_mes 引爆
开场文本单独引爆的条目，在前 10~20 轮里每轮都在。
检出法：在 `first_mes` 文本里逐个 grep 每个条目的触发词。
**修法**：要么改写开场文本里的"设定名词"，要么把该条目触发词改成长词组（插件不支持"且"，只能这样）。

### 3. 表头噪音
`## 名字` + `触发词：…` 每条约 35 字符。命中 43 条/轮 → 1,526 字符/轮（4%）。
- `触发词：` 行对模型零信息量 → 可整体删（省 ~1,010/轮）
- 常态条目的 `## 名字` 也无信息量 → 可折叠（省 ~258/轮）

### 4. 单字/通用词触发词
中文正文里 `鱼 龙 狼 猫 雨 Y` 这类单字必中；`士兵 平民 警卫 贵族 刺客 天使 恶魔 自然 阴影 买` 这类通用词必中。
体积小（单条 24~92 字）但**语义污染**：打斗中途注入"鱼的怪物数据行"。

## 七、跨层重复条目合并（v3.23 流程，2026-09-16 实做验证）

**触发场景**：用户说「世界书和 desc 里重复的条目做合并」「不要出现重复条目」。

### 7.1 五步流程（顺序不能换）

| 步 | 动作 | 脚本 | 关键点 |
|---|---|---|---|
| 1 | **备份** | PowerShell `Copy-Item` 到 `D:\DSH\_backup\merge-<时间戳>\` | 至少 worldbooks.json / characters.json / agent.cordis.yml / desc-clean.txt |
| 2 | **检测** | `dup-detect.mjs` | desc 覆盖率 ≥25% 只抓到 2 条 —— **字面匹配会漏**，必须叠加"标题近似对"检测 |
| 3 | **逐句核** | `dup-unique.mjs` | 每句算 6-gram 落在 desc 的比例，`<40%` 判"该句独有" → 产出**搬移清单** |
| 4 | **执行** | `merge-dedup.mjs` | desc 5 处同步 + 世界书 5 文件禁用 + 构建脚本加守卫；**锚点命中数 ≠1 就 ABORT** |
| 5 | **实测验证** | `merge-delta.mjs` | 用 20 轮真实 `hits` 序列分别在新旧世界书上**重放**，求精确 Δ |

### 7.2 判据：不是"哪边字多"，是「哪边更完整」

| 情形 | 处理 |
|---|---|
| 两边内容等价，一边有独有句 | **保留更完整的一侧，先把独有句搬过去** |
| 一边是**指针**（自称"完整版见 XX"） | 保留被指向的那一侧，指针侧禁用 |
| 名字像但**内容不同**（如同叫"关联词库"） | **不合并** —— 这类占多数，务必逐条看内容 |
| 一边是**指针指向它**（desc 写"完整规则见世界书【X】"） | **不合并** —— 这是设计好的分工，不是重复 |

**本卡实测**：8 对标题近似里只有 **4 对**是真重复；另外 12 条同名条目（信息迷雾·知情范围 / 故事梗概 / 本轮骰池 / 房间规则区 / 规则速查-* …）desc 覆盖率都只有 1%~15% → **全部保留**。

### 7.3 两个必须注意的坑

1. **别按"压缩"处理重复条目**。第一轮我把 `信息迷雾·生成检查` 判成"压缩到 110 字"，
   实际 desc 版比它**更完整** → 正确处理是**整条禁用**，不是压缩。
   **判"重复"之后先问"哪边赢"，再问"怎么改"。**
2. **禁用会连带丢掉结构开销**。插件每条命中都输出 `\n## 名字\n`，
   所以单条回收 = **正文字符 + 条名字符 + 6**（不是只有正文）。
   实测 4 条正文 1,284 → 实际回收 **1,338**。

### 7.4 必须做的"第二轮核查"（宁可多来一轮）

第一轮合并完 **不要收工**。逐句复核每个被禁用条目的**独有句**在 desc 里是否真有等价物：

- 用关键词组核查（`audit-disabled.mjs`）：如「待办铁律」要同时命中 `待办`+`支线`+`日常`。
- 本卡第二轮才发现 **2 条真漏**：「任务完成/失败当轮移出」「待办超限先合并/结转」——
  在 desc 里确实没有 → **补进 desc**（`patch2-taskrules.mjs`），而不是放着丢掉。
- 补丁脚本必须**幂等**（用 MARK 判定）+ **锚点唯一性断言**，否则重跑会重复插入。

| `RX` | 设计常态（本卡 20 条，已过滤 `enabled:false`） | `[目标字符, 动作, 怎么改, 风险, 验证]`（5 元） | 目标 0 = 本条移除 |
| `FXR` | 28 条事实常态 | `[目标字符, 动作, 触发词目标, 内容怎么改, 风险, 验证]`（6 元） | 触发词类动作额外给第 3 项 |

**「每轮省」的算法要分两种动作**：
- 内容改动（删/压缩/下沉）：`省 = 现注入 − 目标字符`
- **触发词类动作**（收窄触发词/加限定词/改为常态）：内容不动，`目标字符` 形同虚设 →
  必须令 `目标成本 = 0`，并给这句后缀：`（把命中率打到 <20% 后，本条基本不再注入）`。
  否则会印出「每轮省 0 字符」这种明显错误的建议。
  检出法：`const triggerOnly = /触发词|限定词/.test(rx[1])`。

### 判定列的两个坑（生成器已修，重写脚本时别踩）

1. **「引用次数」必须算两个来源**：世界书内 `【条名】` 引用 **+** desc 正文里 `【条名】` 引用。
   只算前者会把 `关联词库-因果与转折`（desc 引用 2 次，是 A4/S8 的取词表）误判成"零引用可删"。
   **两者都为 0 才叫真零引用。**
2. **体积阈值要用「注入后」长度**：`本轮骰池` 源 1,469 → 注入 194，
   若按源文判"含详表"会给这条核心机制挂上错误的瘦身建议。
3. 另需一张**人工覆盖表**兜语义判断（机械规则看不出这些）：
   - `玩家声明采纳` → 指针型冗余（自称"完整版见 desc"）
   - `外部设定导入模板` → 极低频（仅"换世界/导入模组"）
   - `记忆锚点` → 面板契约（`[[状态更新]]` 10 分区是归档脚本解析契约，不可删）
   - `触发规则·场景包语义` → 元规则（管插件行为，不是生成行为）

**教训（2026-09-16 实锤）**：只交了世界书清单，用户立刻问

**desc 比整个常态组还大，漏掉它等于漏掉一半**。下次直接从这张表开始，两层一起出。

### 跨文件重复要按「保留更完整的一侧」处理

desc 与 worldbook 会出现**同主题各写一份**的情况（本卡 4 对）：

| 主题 | desc | 世界书 | 保留 |
|---|---|---|---|
| 信息迷雾·生成检查 | 309（更完整：多"知情层级"+传播滞后） | 277 | desc ✅已禁用 |
| 玩家声明采纳 | 156（更完整：多"对NPC行为走检定"） | 159 | desc ✅已禁用 |
| 状态栏模板 | 无独立条目（契约散在【每轮输出契约】） | 623 | desc ✅已禁用 |
| 输出格式与标签白名单 | 【标签白名单】255 | 225 | desc ✅已禁用 |

**判据不是"哪边字多"，而是「哪边内容更完整」**。省下的全在世界书侧，
**desc 侧一个字不删**，避免总账重复计省。

### desc 与 worldbook 的改动风险不对等

| | worldbook | desc |
|---|---|---|
| 改坏的后果 | 少一条规则，模型偶尔不遵守 | **直接影响每轮叙事质量**（它是行为准则） |
| 批次粒度 | 可一次改 3~5 条 | **每批只动 1~2 段** |
| 回归验证 | 跑 20 轮功能验证 | 跑 10 轮**文风回归**：开场轮换 / 句长分布 / NPC 语癖 / 「不是」次数 / markdown 加粗次数 |

## 十、结构性原则（防止复胖）

写入新条目时的分工标准：

| 内容类型 | 应归属 |
|---|---|
| 每轮输出契约（字段/格式） | **常态** |
| 每轮判定的判定公式 | **常态** |
| 查表型知识（数值表/清单/价格表/经验表） | **按需**（关键词） |
| 玩家提问型知识（地点介绍/怪物数据/神祇） | **按需**（关键词） |
| 元规则（管插件行为而非生成行为） | **并进常态主条目**，别单开 |

判定口诀：**"这条每轮都在，是因为每轮真的需要，还是因为触发词太宽？"** 只有前者才配常态。
