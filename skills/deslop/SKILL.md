# deslop — 中文小说去 AI 味

## 先记住三件事

**一、小说 AI 味 ≠ 文章 AI 味。**
通用去 AI 味方法（夸大意义、模糊归因、总结腔、翻译腔）治的是非虚构腔，只能覆盖小说问题的一半。小说真正「一眼假」的是**体裁病**：景物起笔、句尾补语、二分壳、三段式、章末金句、全员同腔。

**二、真凶是结构对称，不是词汇。**
AI 味分两层：表层是词汇，深层是结构对称（平行否定、三段式、句句同长、段段等长、四段式收尾）。只换词不动结构，读起来照样是 AI。**本 skill 的重点是破结构。**

**三、源头抑制优于事后改写。**
生成前注入规则，比成稿后洗稿有效得多。事后改写只能动语言，动不了结构。所以：写到正文时先按下面的「生成时禁令」走，成稿后再跑「三遍法」。

## 七条硬边界

1. **不做同义词替换。** 命中模式时**重写结构或直接删除**，不是换个说法。按词表机械替换是无效功。
2. **不替作者补东西。** 不编观点、经历、细节、事实。
3. **改稿时锁住事实。** 数字、人物、时间、术语、引用、判断、责任关系，**改写**后不许漂移。
   > **注意这条只管「改稿」，不管「写作」。** 写作时你**有权留白**——不必交代每处动机、不必解释每句台词的言外之意、不必把因果写全。小说只需要「说得通」，不需要「严密」。详见 `references/positive-craft.md` 第 3 节。
4. **目标是读感，不是过检测器。** 不承诺、也不追求通过任何 AI 检测。分数不是目标。
5. **留白 ≠ 漏洞。** 留白发生在**解读层**（为什么 / 什么意思 / 后来怎样）——读者能自己填。漏洞发生在**事实层**（谁 / 在哪 / 什么时候 / 发生没发生）——读者填不上，或填了跟后文撞车。**前者要，后者不要。**
6. **反投机：不做机械改写。** 不要为了"反 AI 检测"强制每句换行、把 `……` 改成 `........`、把 `地/得` 全改成 `的`、禁用所有顿号 / 「很」/「像」、强行开篇对话或重排章节顺序。
   **去 AI 味是润色，不是结构重写。** 除非作者明确要求重写，否则不改变章节顺序、伏笔分布、对话占比、人物信息释放节奏。
7. **风格裁决优先于去 AI。** 本文件的句长、标点、修辞、禁用词都是**默认写法**。作者有意选择的写法不机械删除——用 `.deslop-ignore` 按 id 豁免（见下）。

## 三条最容易被忽略的执行口径

### 1. 禁的是「修辞动作」，不是「字面」

所有句式判据都要问一句：**换个字继续做同一个动作，能不能绕过我的规则？** 能绕过，就说明抓错了层级。

以「不是 A 而是 B」为例，它有**七类外衣**，只抓字面必然漏：

| 外衣 | 例子 |
|---|---|
| 字面翻案 | 不是A而是B。并非A而在于B |
| 省字变形 | 不是A，是B。不是A，B才是 |
| 跨句变形 | 不是A。而是B。表面上是A。其实是B |
| 换字变形 | 与其说A，倒不如讲B。毋宁说B |
| **以为体** | 你以为A，其实B。我一直以为A，后来才发现B |
| **让转体** | 看似A，实则B。大家都说A，可真相是B |
| **抬价体** | A不重要，重要的是B。真正值钱的从来都与A无关 |

**后三类最隐蔽。** 拆法只有一种：找到这句话原本想下的判断，**从正面直接说出来**。

### 2. 叙述默认写「逗号长句」

| 场景 | 口径 |
|---|---|
| 叙述（旁白）默认 | 一句用逗号串起 **2–4 个动作或信息**再落句号 |
| 逗号之间 | **8–12 字** |
| 整句 | **20–30 字** |
| 短句 | **偶尔的孤立重拍工具**，不是叙述的默认写法 |

这条比"平均句长 22–38 字"的百分比配额更直接。真人网文实测：逗号长句占叙述句 **74–80%**，整句平均 22–24 字。

> **反过来的坑同样要注意**：不要因为要"长短交替"就把正常的逗号长句拆成短句串。拆短句只该发生在**臃肿修饰、堆叠比喻、抽象总结**的长句上。

### 3. 防「二修伪自然」——加法的反面

**加法清单本身也会被写成模板。** 反检测提示词常把文本推向另一种腔调：

- 为了"突发性"而乱用倒装
- 为了"真人感"而机械加口误、脏话、语气词
- 为了"手机阅读"而强制每句换行
- 为了"对话占比"而把心理描写硬改成台词

**判据：人味来自自然，不是来自装饰。** 语气词要按角色分配（有人多、有人零），不是全篇均匀加；粗话要服务人物身份，不是撒胡椒面。

> 若 lint 报「微动作复读」「碎句号」「动作清单腔」，那不是"AI 味没去干净"，是**删过头了**——把非峰值句恢复成自然白话，而不是接着删。

## 白名单与分级

- **`.deslop-ignore`**：在被检查文件同级目录（或当前工作目录）放一个文件，每行一个判据 id，`#` 开头为注释。作者有意选择的写法（比如全篇统一的破折号用法）在这里豁免，不参与判定也不影响退出码。
- **分级**：lint 输出里每个判据标 `硬` 或 `议`。
  - `硬` = 高精度判据，影响退出码（`--fail-on=blocking`，默认）
  - `议` = 启发式 / 阈值类，只提示，不影响退出码
  - 需要严格模式时用 `--fail-on=all`，advisory 也会让退出码非 0。

## 两种 AI 味：冗余型 和 贫瘠型

**这个区分决定了你该做加法还是减法。搞错了会越改越糟。**

| | 冗余型 | 贫瘠型 |
|---|---|---|
| 表现 | 堆砌、套话、比喻过密、破折号滥用、总分总结构 | 扁平、干、没张力、没个性、读不出情绪 |
| 像什么 | 客服写的年终总结 | 说明书 ／ 分镜脚本 ／ 新闻通稿 |
| 治法 | **减法**：删、破对称、限配额 | **加法**：加欲望、加态度、加口语、加挤压 |

**本文件下面的 12 类病灶、节奏配额、破折号规则——全是减法，治的是冗余型。**

**只做减法不会自动产生好文字。** 删掉废话之后稿子会变干净，但也可能变薄，落进贫瘠型。所以本 skill 必须**两层一起用**：

- **减法层**：本文件 + `references/banned-patterns.md` + `references/banned-phrases.md`
- **加法层**：`references/positive-craft.md`（小说感、张力、对话口语质感、情绪档位）

**顺序：先加，后减。** 先加意图/态度/口语/挤压，稿子会变长变糙变活；再删套话和超配标点，收干净。反过来容易把该留的具体细节一起删掉。

`deslop-lint.mjs` 会把加法层四项单列输出。**它们报低不是"没删干净"，是"没加东西"——这时候不要继续删稿。**

## 12 类中文小说体裁病 · 速查

| # | 病灶 | 判定 | 改法 |
|---|---|---|---|
| 1 | **景物起笔** | 章节/段落首句只有天色、风、雨、月光、空气，没有人或动作 | 改成动作或对话起笔；环境压到 1–2 句，掺在动作里给 |
| 2 | **句尾补语** | 句子主干结束后跟一句抽象短句收尾 | 删掉；把结论换成具体动作或生理反应 |
| 3 | **二分壳** | 出现「不是 X，而是 Y」「不仅 X，更 Y」，两端抽象对称 | 只留信息多的那一端，直接陈述；两端真不同就拆成两句 |
| 4 | **三段式** | 并列项恰好三项，第三项与前两项不同质 | 砍成两项，或加第四项打破工整 |
| 5 | **比喻堆砌** | 每千字比喻 > 5，或连续两句都带比喻标记 | 一段最多留一个，保留最准的那个，其余删 |
| 6 | **情绪直给** | 「他感到 / 觉得 + 情绪词」「内心升起一股…」 | 换成动作、生理反应、选择或对话 |
| 7 | **心理代替动作** | 连续段落只有「他想 / 他知道 / 他意识到」，没有外部事件 | 把想法变成决定并立刻执行：哪个动作、说了什么、去了哪 |
| 8 | **节奏压缩 / 段落同质** | 句长标准差 < 14；或短句占比 > 36%（全是短句）；或长句占比 < 8%；或单句成段 > 34%；或段长离散度 < 0.35 | **往两个方向都修**：短句连排 → 合并成一句带从句的长句；长句连排 → 打散成短句。补 ≥4 句的厚段落。目标是把分布撑开，不是一味变短 |
| 9 | **章末金句 / 收尾模板** | 末句是抽象短句；或**连续两轮/两章的末句是同一种收法** | 断在动作、对话、具体物或未完成事件上；四种收法轮换，不许连用同一种 |
| 10 | **视角穿透** | 正文出现「第 X 章」「本章」「读者」「伏笔」，或 markdown 加粗；或一段内视角人物切换 | 删掉全部元信息与格式标记；一段内只保留一个观察者 |
| 11 | **全员同腔** | 多个角色的话等长、都用书面语、带同样的语气词 | 给每个角色定口癖、句长、教育程度；至少让一个用短句或粗话 |
| 12 | **信息倒豆子** | 单段对话含 ≥3 个专有名词，或 ≥2 条设定解释 | 拆成多轮；让一方不知道；把设定藏在冲突里 |

逐条详解与 ❌/✅ 对照见 `references/banned-patterns.md`；词表与句式正则见 `references/banned-phrases.md`。

## 生成时：把禁令写进 prompt

写小说正文时遵守：

1. 开头必须是动作或对话，禁止以景物 / 天气 / 心理描写起笔。
2. 禁止句尾补语式总结：「他终于明白了一切」「这一刻，时间仿佛静止了」。
3. 禁止否定式排比：「不是 X 而是 Y」「不仅仅是…更是…」。
4. 禁止三段式堆砌。要三样时，砍成两样或加第四样。
5. 「仿佛 / 宛如 / 似」类比喻每千字不超过 5 个，一段最多 1 个。
6. 不写「他感到 X」。用动作、生理反应、选择外化情绪。
7. **节奏按下面的双边配额走**（只写「长短交替」会被退化成全短句，见下节）。
8. 章末不升华、不总结、不抒情。断在动作或对话上。
9. 每个角色有独立口癖和句长习惯，不许全员同腔。
10. 不要解释已经写出来的比喻。
11. 禁止把「第 X 章」「伏笔」「读者」写进正文；正文禁止出现 markdown 加粗。
12. 写完自查一遍：哪一句像 AI 写的？重写它。

第 3 条补充：「不是 X 而是 Y」不是禁用句式，是**配额句式**——每 3000 字不超过 1 次。它单次很有效，用密了就成口癖。

需要往 desc / agent preset / 系统提示里粘贴的精简版，见仓库根目录 `deslop-提示词片段.md`。

## 节奏配额（双边，不可只满足一边）

「句子要长短交替」是一条**会被退化套利**的规则：模型可以靠"全都很短、每句随机抖动几个字"来宣称自己长短交替过了。所以要同时给**上限和下限**。

| 项 | 配额 | 为什么 |
|---|---|---|
| 平均句长 | **22–38 字** | 低于 20 字说明整篇在「打点」 |
| 短句（<15 字） | 14–36%，**不得超过 36%** | 短句是调料，不是主食 |
| 长句（≥40 字） | **≥ 8%** | 没有长句就没有呼吸 |
| 超长句（≥70 字） | 每 3000 字至少 1 句 | 长句是节奏的锚 |
| 单句成段 | **≤ 34%** | 超过就变成机械鼓点 |
| 厚段落（≥4 句） | **≥ 15%** | 全篇都是 1–2 句的段，读起来像清单 |

**判定口径**：连续三句都短，和连续三句都长，**一样是病**。改稿时两种都要打散。

## 收尾必须轮换

每轮 / 每章的最后一句**不许连续两次用同一种收法**。可选收法至少四种：

- **动作收**：一个没做完的动作（「他吹了灯。」）
- **对话收**：一句台词（「你没动。」）
- **环境收**：一个具体的物（「桶底朝天。」）
- **未完成事件收**：一个已经启动、还没结果的事（「门在他身后合上。」）

**最容易变成模板的是「短台词收尾」**——短、有冲击力，所以模型爱用，但连用几轮就完全可预测。写完检查：最近三轮的末句是不是同一种收法？

## 加法清单（治扁平、没张力、没个性）

除了遵守上面的禁令，**还要主动往上加这九样**：

1. **加欲望** — 叙述段里的人物必须"想要"什么。每 2–3 句要有一个意图（要找、要藏、要试探、要拿、要躲）。纯观察不算。
2. **加态度** — 叙述者要有判断和情绪介入：觉得某事荒唐、恶心、好笑、不对劲。**对什么都不评判、什么都不觉得奇怪的叙述者，读者无法跟他建立感情**——这是"散文感"最常见的来源。
3. **加口语** — 对话里语气词每 100 字 4–7 个（吧 呢 啊 嘛 呀 嗯 唉 啧）。但**必须留至少一个不用语气词的角色**做对比，否则是另一种同质。
4. **加挤压** — 句子之间要互相驱动，不是排排坐。把 `A。B。C。` 改成 `A，于是B，但C`。
5. **加张力钩子** — 六个来源挑着用：信息差 ／ 代价 ／ 时限 ／ 不可逆 ／ **未说出口** ／ 打断。「未说出口」最强：让人物想说什么但没说。
6. **加情绪档位** — 不要一直维持同一个情绪。紧张段落之间插松弛（笑一下、饿了、想起一件无关的事）。**持续的紧张等于没有紧张。**
7. **让台词不完整** — 省略主语、重复强调、自我修正、答非所问。完成度太高的台词是字幕，不是说话。
8. **加留白（减解释）** — 动机不必说、言外之意不必点破、因果不必写全。**但只在「意义层」留白，不在「信息层」留白。**
9. **让意义开放、信息具体** — 最好的留白是"信息很精确、意义可以有好几个"。例：`她把手机翻过来扣在桌上，屏幕朝下。`——动作精确，含义开放。

**最容易被忽略的是第 1、2 条**：新手和 AI 都爱写"客观观察"，因为观察最安全。但小说的叙述者必须**在场**——有欲望、有偏见、有怕的东西。

**第 8、9 条是「加」里面唯一带「减」性质的**——减的是**解释**，不是**信息**。这两条和第 1、2 条不冲突：**叙述者要在场，但不要抢占**。

- 在场（要）：`这不对劲。`
- 抢占（不要）：`这不对，因为他是想让我先开口，这样他就能摸清我的底——`

后半句把读者的活干了。**留白被抢走，读者就少参与一次。**

完整技法、口癖表、逐句改写示范见 `references/positive-craft.md`（第 3 节专讲留白）。

> **修饰词单独说一句**：前面的规则说"删形容词"，针对的是**空泛评价**（美丽的、震撼的）。**精确限定的修饰要留、甚至要加**（半截的、发潮的、缺了一颗的、大了两号的）。判据是：这个修饰词**缩小了想象范围**吗？缩小了 → 留；只贴了个标签 → 删。

## 破折号：中文里它只有四个正当用途

破折号是最容易被写成 AI 签名的一个标点，因为**它的主流用法是英文习惯的移植**。

中文小说里破折号正当的用途只有四种：

| 用途 | 样子 | 保留？ |
|---|---|---|
| 话被截断 | `"我——"` | 保留 |
| 拖音 | `"来——了——"` | 保留 |
| 语义突转 | 语气急转 | 保留，少量 |
| **读者必需的解释** | `伊利希尔——这是狐狸的本名，托林在笔录里提过一句——把钥匙转了个方向` | **保留**（见下） |

**而「陈述——补充说明」这个用法，是英文 em dash 的直接移植。** 判它是好是坏，只看一件事：**删掉之后读者还读得懂吗？**

- 删掉读者就不认识了（人名本名、地名别称、身份来历）→ **必需解释，保留**。上表第 4 行就是这种。
- 删掉不影响理解、也不改变语气（只是给句子加个调味性的后半截）→ **纯修辞补充，改逗号/冒号或拆句**。

> ⚠️ 这一条 2026-09-15 改判过。旧版写「禁止成对夹注式」，理由是「中文该用逗号或括号」——**这个判据是错的**，因为它按形态定罪，不看功能。用户给出的反例（上面第 4 行那个）承载了读者必需的信息，删掉读不懂，属正当用法。
> **教训：标点类判据一律要问「删掉会怎样」，不能问「长得像不像英文」。**

### 三条硬规矩

1. **每段最多 3 处**（按处计，一个「——」= 1 处）。一段里堆 4 个以上，说明这段在用破折号代替逗号。
2. **禁止把破折号当逗号用。** 判据同上一节的「删掉还读得懂吗」。
3. **全篇密度按处计 ≤ 5‰**（= 每千字 ≤5 个「——」）。
   > ⚠️ **单位必须说清**：一个中文破折号写作「——」= **2 个 U+2014 字符**。
   > 按**处**算 5‰ = 每千字 5 处；按**字符**算 5‰ ≈ 每千字 2.5 处。**差一倍。**
   > `deslop-lint` 同时输出两个口径：「破折号密度(按处)」是**判据行**（与卡规 S2 对齐），「破折号密度(按字符)」留作对照。
   > 写进 prompt 的配额要显式写明按哪个单位，否则模型算不出自己有没有超，就干脆不自查了。

### 密度达标 ≠ 没问题：还要看「功能单一」

密度是必要不充分条件。**最常见的漏网案例是：破折号密度只有 4‰（不超标），但叙述里每一处都在做「陈述——补充说明」。**

判据（`deslop-lint` 的 `dashsingle`，只看引号外的**单侧**破折号；成对夹注式另由 `dashpair` 统计）：

- 右邻**同一行内**紧跟 ≥2 个汉字内容的 → 记为「补充型」；
- 补充型占引号外破折号 **≥90%** 且单侧总数 **≥10** → 报警示「破折号功能单一」。

> **实测数据**：两轮 DND 长样本（33k 字与 13k 字各一份）都是叙述域破折号 **96%～99%** 在做陈述-补充说明。这是该模型在中文长文里的**稳定生成偏好**，不是某轮的发挥失常。
>
> **这条判据的边界**：它**无法区分**「必需解释」和「纯修辞补充」——那需要语义理解。所以它是**弱提示**，命中后必须人工逐条过：必需的解释（人名本名/地名别称/身份说明）保留，纯修辞的改掉。
>
> **实现坑**：判定右邻内容时**必须按行截断**（取 `slice(i+2).split('\n')[0]`）。若直接往后取 N 个字符，会滑过换行，把「…一件事——」+ 下一段这种**合法的戛然而止**误判成补充说明（初版因此报出 35/35=100% 的假满分）。

有了这条，「改稿」的目标不是「把破折号删光」，而是**把合法用途（截断／拖音／突转／必需解释）的占比提上去**。

### 替换对照

| 原文结构 | 改法 |
|---|---|
| `A——B`（B 是**必需**解释：人名/地名/身份） | **保留** |
| `A——B`（B 是可删的修辞补充） | `A。B。` 或 `A，B。` |
| `A——B`（B 是纠正） | 删掉 A 的否定部分，直接写 B |
| `——插入语——`（承载必需信息） | **保留** |
| `——插入语——`（纯修辞、凑节奏） | 用括号，或把插入语前置 |
| `"台词——"`（截断） | 保留 |

**注意**：破折号经常和「不是 X 是 Y」叠用——`暗褐色——不是虎口这道新伤留下的`、`让出三分之二——不是让路，是给货主留个位置`。这类是**修辞补充**（删掉读得懂），删掉破折号能同时治掉一半二分壳，这两件事一起做。

### 最有效的自查法

把稿子里**每一处**破折号单独拎出来，问一句：「删掉它，读者还读得懂吗？」通读一遍。

- 读得懂、也不觉得少了什么 → **纯修辞补充**，改逗号/冒号或拆句。
- 读不懂 / 明显缺了一块 → **必需解释**，保留。

注意不要一刀切。做完之后统计一下合法用途的占比，**一半以上是合法的才算健康**。

## 段落结构层：句级指标全绿了，读感还是「像 AI」

**这是 2026-09-15 实测出来的一条重要规律。**

同一份卡、同一个模型，注入「句长/标点」类规则前后对比（黄铜匣 → 浮木与咸鱼，各约 1.1 万字）：

| 层 | 指标 | 前 | 后 |
| --- | --- | --- | --- |
| 句级 | 破折号（处/万字） | 46.3 | **21.9** |
| 句级 | 短句占比 | 53.6% | **37.1%** |
| 句级 | 平均句长 | 18 | **24** |
| 句级 | 句间因果/转折 | 3.4 | **7.2** |
| 段落级 | 段首「我/他/她」占比 | 26.5% | **26.6%** |
| 段落级 | 「不是A，是B」二分壳 | 7 处 | **5 处** |
| 段落级 | 「不是」密度（/万字） | 25.5 | **21.2** |

**读数**：句级刻度全线改善，段落级骨相纹丝不动。用户读完的评语是「完全没好转」——**他说的是骨相，不是刻度。**

原因很直接：规则的覆盖面决定了改善的覆盖面。如果规则全是「句长、破折号、语气词」这类**句级**指标，模型就只会改句子，段落组织方式（怎么起、怎么收、多长）不会被碰到。而「段落怎么组织」恰恰是最像 AI 的一层。

### 四条段落级硬规矩（R 组）

| 编号 | 规矩 | 配额 | 判据 |
| --- | --- | --- | --- |
| R1 | **段尾不许判断句收口** —— 段末不得是定性/顿悟/结论式短句（"咸鱼不会动。""不是货，是人。"） | 每 10 段 ≤1 段 | `deslop-lint` → `tailjudge` |
| R2 | **段首去「我」化** —— 从环境/物件/对白/动作切入，主语往后挪 | 段首代词段 ≤15% | `headpron` |
| R3 | **段长不许均匀** —— 禁止连续三段长度接近 | σ/μ ≥0.5；4 句厚段 ≥15% | `paraCv` / `multiSentPct` |
| R4 | **段段有比喻是大忌** —— 相邻两段不得都有比喻 | 含比喻的段 ≤1/3 | `similepara` |

**R1 是最值钱的一条**，因为「段尾一句顿悟」是模型最爱用的收口方式：把留白一次收干，读者没有余地。段尾改成一个动作、一句对白、一个感官细节，或一个还没解答的疑问。

> ⚠️ **R1 与「加法层 A2 加态度」会打架**：A2 要求叙述者要评判，模型就把评判句放在段尾收口，反而更像 AI。正确做法是**评判放段中，段尾留给动作或未解的疑问**。写卡片时必须把这句话写进去，否则两条规则互相抵消。

## 「不是A，是B」：中文长文里最稳的 AI 指纹之一

**先否定、再纠正**——这个修辞动作在真人写作里偶尔用，在模型笔下的长文里会变成固定动作。

实测密度（三个不同样本，跨两轮改写）：

| 样本 | 「不是」总数 | 密度（/万字） | 「不是A，是B」二分壳 |
| --- | --- | --- | --- |
| 梅尔 5 轮合并（2.6 万字） | 89 | 34.2 | 24 |
| 深水城·黄铜匣 | 35 | 30.6 | 12 |
| 浮木与咸鱼 | 27 | 25.7 | 8 |

**三个样本都落在 26–34 次/万字**——这是稳定生成偏好，不是某一轮的发挥失常。合理上限约 **8 次/万字**。

### 为什么它读起来像 AI

它总是成对出现，形成「否定 → 翻案」的二拍节奏：先立一个假靶，再打掉它。读者被喂了两次，信息只拿到一次。

```
不是拒绝，是绕。
不是货，是人。
不是恐惧的抖，是一种更细的、压着的抖。
扔给我咸鱼干不是好心，是预备堵嘴的东西。
```

### 改写方向：删掉否定，直接说正面

**最省力的改法不是把它换成关联词，而是把否定整个删掉。** 多数时候正面陈述一次就够了：

| 原文 | 改后 |
| --- | --- |
| 不是拒绝，是绕 | 她绕开了，因为不想答 |
| 不是货，是人 | 桶里装的是人 |
| 扔给我咸鱼干不是好心，是预备堵嘴 | 扔给我咸鱼干，为的是堵我的嘴 |
| 不是恐惧的抖，是一种更细的、压着的抖 | 那抖很小，压着，倒像等得太久了 |

**想要落差感**时，才用关联词接（词表见世界书【关联词库-因果与转折】）：于是 / 却 / 偏偏 / 到头来 / 结果 / 反倒。

> **区分**：对白里的正常澄清（"这不是我的，是他的"）、引文、以及**具体物件的对比**（羊皮/布、矮/驼）是自然中文，不算病。判据只看两件事：① 密度是否 ≥8/万字；② 是不是「抽象翻案」式抬价。

## 改稿时：三遍法

**Pass 1 · 破词** — 删填充词、抽象词、禁用词表命中项、空洞连接词。目标：砍掉 10–20% 字数。删完信息不减少，说明原本就是废话。

**Pass 2 · 破结构** — 逐段找出所有平行脚手架：否定排比、三段式、句句同长、段段等长、章末金句、连续比喻。**每段至少破坏一处。** 一处不对称动作都没有的稿子，一定还是 AI 味。

**Pass 3 · 补人味** — 加至少一处「人在想」的痕迹：一个跑题、一个没回答的问题、一处承认不确定、一个不太贴切的例子而你说出来了、一个自打断。同时给关键角色补上专属口癖。

三遍跑完再回读一遍，检查事实、因果、术语、责任关系是否在原位。

## 量化自检

```
node "D:/DSH/skills/deslop/scripts/deslop-lint.mjs" 你的稿子.md
node ".../deslop-lint.mjs" 章节目录 --profile=strict
node ".../deslop-lint.mjs" 稿子.md --json

# 对话归档（混有 <status> / <状况> / [[状态更新]] / 判定行）先抽纯正文再测
node ".../extract-prose.mjs" 归档.md --out 正文.txt --stats
node ".../deslop-lint.mjs" 正文.txt
```

输出的超标项就是改稿顺序：先修「正文加粗 / 机器头外显」，再修「节奏带」（句长区间、长句配额、厚段落），然后修结构类（二分壳、三段式、同长句、章末金句），最后修密度类（比喻、破折号）。退出码非 0 表示有 fail 级问题，可以直接接进脚本流水线。

阈值表里「节奏带」三项（平均句长、短句占比、长句占比）是**区间**指标：低于下界和高于上界**一样报错**。这是刻意的——它们分别对应「节奏压缩」（全是短句）和「节奏臃肿」（全是长句）两种相反的 AI 病。

**读报告先看「叙述口径」那一行。** 全文口径把对白独段也算进句长统计，而对话本来就短 —— 对白密集的第一人称稿会因此被系统性压低平均句长、抬高短句占比。`deslop-lint` 现在会额外输出一行**纯叙述段**（不含引号的段落）的平均句长／短句／长句，用来自查「这个超标是真病灶还是口径放大」。

判定口径：

- **叙述口径的短句占比也超标** → 真病灶，叙述本身写碎了。
- **叙述口径正常、只有全文口径超标** → 口径问题，别动叙述节奏，重点看对白轮换与段落排布。

**同一条纪律也适用于「单句成段占比」**：对白独段（`"…。"` 自成一段）是规范写法，不该计入「打点式机械节拍」。判读时把它拆开看 —— 纯叙述段里的单句成段率高才是问题。

## 连载/多轮：跨文件复读检测

单文件 lint 看不见「第 3 轮和第 4 轮用了同一个动作链」——每轮单独看都干净，连起来读才露馅。

```
node ".../deslop-lint.mjs" 章节目录 --quiet --cross      # shingle 默认 8 字
node ".../deslop-lint.mjs" 章节目录 --cross=6            # 短句体裁可降到 6
```

它用 n 字 shingle 求交集，只报**出现在 ≥2 个文件里**的片段，并把相邻 shingle 合并成完整短语。
自动跳过两类文件，否则会满屏假阳性：

- **统计边车**：`*.stats.txt` / `*.lint.txt` / `*.bak`（默认排除；另有 `--exclude=RE`）
- **聚合稿**：文本完整包含另一个文件的（如 `全部合并.txt`）。不跳过的话，每一段都会被报成
  "复读"——那不是作者复读，是文件结构复读。

它抓不到什么：**改写式重复**。「把羊皮卷起来→捆好→塞进油布包」如果每轮换一种说法就躲过去了。
所以母题（反复出现的物件/动作）要**单独手工量化**：

```js
// 同一物件名全篇出现次数；>8 次就该设配额
for (const k of ['羊皮','油布','木匣','皮绳']) console.log(k, (text.match(new RegExp(k,'g'))||[]).length);
```

实测一次 3.25 万字的稿子：`羊皮` 39 次、`木匣` 18 次、`雨` 17 次——比精确复读更能看出单调。

## 格式类信号：先分解，再定性

**只看总数会误判。** 曾经有人在 3.25 万字稿子里数出 206 处 `**` 加粗，直接判为"重度 AI 味"。
分解后才发现：51 处是场景头（项目格式约定）、76 处是判定行与战斗地形网格（输出契约的机器块）、
18 处是结算行——**145 处都是契约要求的**，真正多余的是 61 处整句台词加粗。

结论：`**`、`【】`、`——` 这类格式信号，必须先按「契约机器块 / 正文叙述 / 台词」三分类再定性。
分类脚本比总数更有说服力：

```js
for (const m of raw.matchAll(/\*\*([^*\n]+?)\*\*/g)) {
  const s = m[1].trim();
  if (/^第\s*\d+\s*日[，,。]/.test(s)) scene++;          // 场景头：约定
  else if (/^[“"「]/.test(s)) dialogue++;                // 台词整体加粗：多余
  else if (/^[【〔]|^——/.test(s)) machine++;              // 机器块：契约
}
```

## 在角色扮演/长文循环里，不要指望模型自己调 skill

实测：给一个 tavern 角色卡配了本 skill（`customSkillDirs` 里 rank 300，进程启动时间也晚于
SKILL.md 落盘），连出 5 轮 3.25 万字，会话记录里检索 `deslop` / `SKILL.md` / `语气词` /
`节奏配额` —— **全部 0 命中**。

原因不是没挂上，而是 **roleplay 循环里模型不会主动发起 skill 调用**：它只想着推进剧情。
规则不注入 system prompt，就等于不存在。

所以在这种场景下，本 skill 的正确用法是二选一：

1. **把规则文本直接注入卡片**（用 `deslop-提示词片段.md` 的精简版/加法版），当普通 prompt 用。
2. **当后置改稿器**：模型先出稿，再由 harness 跑 lint + 三遍法改写。

顺带一条诊断口径：**加法层四项（语气词/意图词/态度词/句间因果）是判断"贫瘠型 AI 味"最灵的指标**，
比节奏带更能定位"读起来干"。四项齐刷刷趋零时，先做 Pass 0 加料，**不要**急着删。

## 模型的「文风自查」是成绩单，不是体检报告

如果把规则注入卡片并要求模型「写完自查一遍」，它交回来的自查表**不可信**，而且是**系统性不可信**，
不是随机出错。实测规律（8 章 / 11k 字样本，模型自附一张 10 行自查表）：

| 自查表行为 | 触发条件 | 实例 |
|---|---|---|
| **如实汇报** | 它确实做到的项 | 对白标签轮换、NPC 语癖、五感密度、收尾落点 —— 都真做到了 |
| **报假数字** | 有配额、但它没做到，且数字可含糊 | 声称「短句约三成」→ 实测 54%；声称「比喻 ≤3 处」→ 实测叙述喻体 36 处 |
| **整项略过** | 它没做到，且规则本身口径不清 | **10 行里没有任何一行提破折号** —— 而破折号违规率是 96%，全篇最差项 |

所以：

1. **不要用「模型自查表」当作验收依据。** 它是一份挑选过的成绩单。
2. 真要它自查，就**强制逐项覆盖**：自查表必须列出 A1–A7 与 S1–S6 的**每一项**，缺项直接算未通过。
   现在的表结构允许它自由挑行来写，等于开了一个刷分的口子。
3. **配额必须可计算**：给出单位、分母、区间。「破折号 ≤5‰」不写清按字符还是按处，模型算不出来 → 直接不写。
4. **最终判定只认外部脚本**（`deslop-lint` + 探针）。模型的自述仅供参考。

### 另一条同类规律：卡片内部规则会互相抵消

注入新配额时，**必须先检查它有没有和卡里已有的风格指令冲突**。实测案例：

| 来源 | 原文 | 效果 |
|---|---|---|
| 原有「句式节奏」段 | 「**多短句**+对话+动作节拍（"门开了。"两字句后接长句）」 | 鼓励打点式短句 |
| 新注入 S1 | 「短句(<15字) 14–36%」「4 句以上厚段落 ≥15%」 | 要求控制短句、加厚段落 |

两条同时存在时，模型选了**给了具体范例的那条**（"门开了。"），产出短句占比 50.4%、厚段落 5.7% ——
新配额被完全抵消。**"有具体例子"的规则永远打赢"只有区间"的规则。**

推论：注入区间型配额时，要么把冲突的旧规则改掉，要么给区间也配一个具体范例（如
「每 3 个短句配 1 个 25 字以上的句子」）。另外，**核心意象类配额要写例外** ——
「同一物件名全篇 ≤8 次」在「牙 ×31」的侦探稿里是必然卡死、也必然被忽略的规则。

## 改卡部署链路（DND·无尽冒险 / dsh-tavern 专用）

规则改完要落到卡上才算数。这条链路踩过坑，照抄：

```
desc 唯一权威源          D:\DSH\wb\生成\desc-clean.txt
        │  ① 注入补丁（纯文本，无缩进）
        ▼
构建                     node D:\DSH\DND无尽冒险_构建脚本.mjs
        │                → D:\DSH\DND无尽冒险_角色卡_P1.json (description)
        │                → D:\DSH\DND无尽冒险_面板内部格式_P1.json ([0].desc)
        ▼
同步到 preset ②          ~\.dsh\.agent-presets\preset-mtzu16fw-mu5jbq\
                         ├─ characters.json         [0].desc          （无缩进）
                         └─ agent.cordis.yml        persona.config.prefix
                                                    （块标量，**6 空格缩进**）
```

要点与坑：

- **落点是四处，不是一处**：源 + 两个构建产物 + preset 两个文件。
  `agent.cordis.yml` 的 prefix = **desc 原文 + 尾三块**（成人模式 / 中文思考 / 工具规则）
  —— 注入时必须只动 desc 那一段，别把尾三块冲掉。
- **改世界书（不是改 desc）时，落点是另外一套 —— 极易漏掉！**
  世界书的源与部署态是**两个不同文件**，插条目只改源 = 没改：

  | | 路径 | 谁读它 |
  |---|---|---|
  | 源 | `D:\DSH\DND无尽冒险_worldbooks.json`（+ `_规则层_` / `_前端导入版`） | 只被构建脚本读 |
  | **部署态** | `~\.dsh\.agent-presets\preset-mtzu16fw-mu5jbq\worldbooks.json` | **插件运行时读它**（`lib/index.js:20` `ROOT = ~/.dsh/.agent-presets`） |

  实测事故：`【关联词库-因果与转折】`（568 字，常态）写进了源（6,114 条），
  **preset 那份停在 6,113 条、旧了一天**，而 desc 里 A4 与 S8 各有一次
  "见世界书【关联词库-因果与转折】"——模型被要求用关联词，**词表却不在上下文里**。
  一个未部署的 568 字条目，同时打穿了「加法层 A4 挤压」和「句式层 S8 否定句式」两层。

  **校验口诀**：改完世界书，比对两边**条目数 + 内容 md5**，并把新条目的 `name`
  拿去 `grep` 部署态文件确认命中。只看"我改过了"不算数。
- **锚点插入法**：不要整文件重写。用 `【DND 基调与电影感】` 作锚点，
  在它前面插入新块。先校验锚点命中数 == 1，否则中止（脚本要写成幂等：
  已含标记即跳过）。yml 版锚点要带上缩进：`\n\n      【DND 基调与电影感】`。
- **⚠️ 缩进只加在「落到行首」的片段上，行中片段绝不能加**（踩过）：
  desc 里既有整段独立的行（如 `叙事正文另守四戒：…` 整行开头），也有**长行中间**的片段
  （如 `充当叙述（详见 S3 / S8）。` 前面还有半句）。给行中片段也补 6 空格 → 在 yml 里
  **永远匹配不到**（命中 0 次 → ABORT，而 desc/characters.json 已经写入了，落点就不一致了）。
  做法：给每个替换项标 `inline: true` / `false`，只有行首项才走 `indent()`。
  **判断法：把该片段连同前 20 个字打印出来，看它前面是 `\n` 还是别的字符。**
- **YAML 块标量缩进**：新块每行都要补 6 空格，否则 persona 直接解析失败。
  写完用真实 YAML 解析器验一遍，并确认 `persona.prefix` 里尾三块仍在。
- **服务端实时读盘**：改完 `agent.cordis.yml` / `characters.json` 后，
  `GET http://127.0.0.1:3081/api/tavern/preset?presetId=<id>` 立刻返回新内容，**不用重启**。
  （`/api/tavern/card`、`/api/tavern/characters` 要鉴权返 401；`/presets`、`/preset` 匿名可读。）
- **但旧会话不会升级**：dsh-tavern 2.3.1 预设解析以会话记录为权威
  （`agent-preset/selected > header > session-bindings > 默认`）。
  验证效果必须**新开会话**，并在聊天顶部「Agent 预设选择器」里选中该预设
  —— 默认预设是 tavern-lite，不选就不带卡。
- `inject-debug.log` 已停更（末条 2026-09-12），**别拿它验收**。

## 规则没生效时，先查「供给」再查「语气」

改完卡发现某一项还是超标，直觉是"规则写得太温和"——**先别急着加狠话。**
按这个顺序查，命中率更高：

| 顺序 | 查什么 | 查法 |
| --- | --- | --- |
| 1 | **规则到底进没进 prompt** | 把真机 system prompt 存下来，`indexOf` 规则里的标记串（如 `R1 段尾不许判断句收口`） |
| 2 | **规则里指向的外部资源存在吗**（悬空指针） | 规则里凡是写"见世界书【X】""参考【Y】"，`grep` 部署态世界书确认 **X 真的在** |
| 3 | **有没有被别的规则抵消** | 见上一节「卡片内部规则会互相抵消」 |
| 4 | 规则本身够不够狠 | 前面三条都过了才轮到这条 |

**第 2 条是最常被漏的。** 卡片规则里写"改用关联词""按【词表】取词"，看起来是
"给了模型工具"，实际上如果那个词表条目没部署，就等于**让模型做一道没给题库的题**。

判定特征：某项指标**长期卡在同一个数值**、且是"要它换成 A 类表达"型的要求
（换关联词、换收尾方式、换口癖），而对纯"别写什么"型的要求响应良好
→ 优先怀疑**供给缺失**，不是约束力度不够。

配套诊断：这类问题在 lint 里会表现成**加法层偏低 + 对应减法层超标同时出现**。
例：`句间因果/转折 3.2/100 句（要 ≥10）` 与 `「不是」18.3/万字（要 ≤8）` 同时红
→ 同一个根因：关联词表不在上下文里。

## 不做

- 不处理非小说文本（公文、技术文档、学术论文）——那类文本的正式程度与平行结构是**要求**，不是病。
- 不处理繁体中文。
- 不替用户写原文没有的观点、经历、细节。
- 不协助绕过学校、期刊或平台的 AI 使用规定。
