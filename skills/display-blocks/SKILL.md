# 输出展示块（dsh-display-blocks 契约）

**一句话**：渲染器只给**骨架**，结构由你自己声明。块里想开几节、节叫什么、每节放什么形状的内容、
什么颜色 —— 全部写在 JSON 里，没有「只认某几种槽位」的限制。

渲染侧代码：`D:\DSH\display-blocks`（`lib/{spec,parse,render,client}.js`，42 项夹具）。
本 skill 的自检脚本直接 import 那份词表，所以**规则不会漂**。

## 一、硬格式（违反了就不渲染，会被当成普通文本）

```
[[标记]]{"名":"标题","类型":"人物","稀有度":"传说","节":[...],"备注":"…"}
```

1. `[[标记]]{` 之后必须是**一行合法 JSON**：不得用单引号、不得有尾逗号、必须用 ASCII 双引号 `"`
   （中文引号 `“ ”` 会直接解析失败）。
   > 「一行」是**契约要求**，不是解析限制：本插件的解析器用大括号配平，跨行的 JSON 其实也能读
   > （`JSON.parse` 允许空白）。但 DND 皮肤按**行首**分流、流式输出被截断时也更脆 —— **照一行写**。
2. 块**可以**出现在正文任意位置，但**推荐独占一行**（皮肤侧的分流按行首匹配，最稳）。
3. **标记由你决定**：`[[人物]]`、`[[秘宝]]`、`[[预言]]` 都行，不在词表里就用兜底样式。
   想新增一种信息卡，直接发明标记即可。
4. 说明文字里的 `[[商店]]`（后面没有 `{json}`）**不会**被误判成块 —— 可以放心引用。

## 二、分节：结构自己长（主力用法）

人物卡这样写，**不需要**把七项挤进一张扁平表：

```
[[人物]]{"名":"凯尔本·「黑杖」","类型":"人物","稀有度":"传说","节":[{"名":"年龄","值":"127 岁（人类外表约四十）"},{"名":"外貌","值":"白发及肩，左手一枚龙鳞戒"},{"名":"身材","值":"精瘦，比看起来更有力"},{"名":"心理","值":"表面从容，实则多疑"},{"名":"服装","值":["玄色长袍","龙鳞胸甲","黑杖"]},{"名":"状态","色":"橙","值":{"生命":"良好","伤势":"无"}},{"名":"技能","布局":"标签","值":["焰击术","传送术"]}],"备注":"他不喜欢被反复打扰。"}
```

**版式默认「自动」，按值的 JSON 形状自己挑** —— 多数时候你什么都不用写：

| 值的形状 | 渲染成 |
|---|---|
| 字符串 / 数字 | 一整段（仍走行内标注，`（传说）` 照样上色） |
| 数组 | 逐行列表（元素是对象 → 条目小卡） |
| 对象 | 两列键值表 |

要强制就写 `"布局"`：`文本` / `键值` / `列表` / `标签`（标签 = 一行胶囊，适合服装、身材、技能名这类短值）。
`"图标"` 可给单节换图标（默认图标见 `references/contract.md`）。

**四种写法都认**，挑最省事的：

| 写法 | 例子 |
|---|---|
| 描述对象数组（最完整） | `[{"名":"外貌","图标":"👁","布局":"文本","值":"…"}]` |
| 映射（最省字） | `{"年龄":"27 岁","身材":"精瘦"}` |
| 单键对象 | `[{"外貌":"白发"}]` |
| 描述字段外全是内容 | `[{"名":"外貌","身高":"175","发色":"银白"}]` → 剩余键自动变这一节的键值表 |

- **节名不在词表里照样渲染**（只是没默认图标）；要默认图标/默认色才动【展示规范】。
- **可以嵌套**：某一节的值里再写 `节`（上限 4 层）。
- **空节不画**（空字符串 / 空数组 / 空对象直接丢弃）。

## 三、颜色：四级回落

```
卡片强调色：色 → 稀有度 → 该类型的词表默认色 → 兜底褐
节  强调色：色 → 本节稀有度 → 该节的词表默认色 → 继承卡片
条目名    ：色
行内      ：[g]…[/g] ／ [血红]…[/血红] ／ [#00e5ff]…[/#00e5ff]
```

- `色` 可以写 `#8b0000`、`紫`、`gold`，也可以直接写**稀有度词**（`传说` → 词表里的金色）。
- **写了 `色` 就用它**，压过稀有度；都没写才用类型 / 节的默认色。
- 稀有度**胶囊**永远显示稀有度自己的颜色 —— 用 `色` 改卡片强调色不会把胶囊染错。
- 认不出来的色值只是**跳过这一级**，继续回落，不会吞内容。

## 四、行内标注

| 写法 | 效果 |
|---|---|
| `（传说）` `【传说】` `[传说]` | 按稀有度配色（同色系胶囊）；**词表命中**才成立，词表外的 `（某某）` 原样保留 |
| `[g]文字[/g]` | 金色（短码：`g` `y` `o` `r` `p` `b` `c` `gr` `m` `w` `k`） |
| `[血红]文字[/血红]` | 中文/英文色名（30+ 条，见 `references/contract.md`） |
| `[#00e5ff]文字[/#00e5ff]` | 任意颜色 |
| `[g]获得（传说）之刃[/g]` | 嵌套：整体金色 + 词内传说色 |

颜色标签必须**命中词表且有闭合**才成立 —— 所以 `[传说]` 和 Markdown 链接 `[文字](url)` 都不会被误吃。

## 五、写作纪律（防退化：别用最省力的方式满足字面要求）

1. **块只装结构化数据，正文照常叙事。** 不要把整段剧情塞进块里 —— 块是卡片，不是容器。
   一条回复里同类型块 ≤ 2 个（列表类可到 5 个）。
2. **分节数量 3~8 节**。少于 3 节说明不值得分（直接用 `字段`）；多于 8 节说明该拆成两张卡。
   每节正文 **20~120 字**；单节超过 150 字就拆节或改用 `列表`。
3. **不要每节都标稀有度。** 稀有度只标在**真的有档次之分**的实体上（人物/物品/地点/技能）；
   年龄、外貌、心理这类**不要**标。
4. **一张卡里不同颜色 ≤ 4 种**（不含稀有度胶囊自带的色）。同类信息用同色 ——
   颜色是「分类信号」，不是装饰；满卡彩虹等于没有信号。
5. **别写占位节**（空值、`"？"`、`"待定"`）。空节会被丢掉，写了只是浪费 token。
6. **块的字段名用中文规范键**（`名` / `类型` / `稀有度` / `节` / `字段` / `条目` / `备注`）——
   英文别名虽然认，但中文键更短、更省 token；混用会让后续维护变累。

## 六、自检（改完一定要跑）

```bash
node C:\Users\m0408\.dsh\skills\display-blocks\scripts\check-blocks.mjs <文件路径>
# 或从 stdin 读： ... check-blocks.mjs -  < draft.md
# 打印现行词表（写文档/查色名时用）： ... check-blocks.mjs --dump
# 证明校验器本身没坏：      ... scripts\selftest.mjs
```

脚本用**插件自己的词表**校验：单行 JSON、ASCII 引号、键名、节的形状、布局名、颜色是否可解析、
稀有度是否命中。**它不静默通过** —— 出现 `[[` 却解析不出块会硬报错并非零退出
（尾逗号 / 单引号 / 中文引号都会被拦下）；`selftest.mjs` 用 7 个样本证明这一点。

## 七、把契约装到别处

**装到某张角色卡**（角色扮演时模型自己就会照着输出）—— 走 tavern 的幂等追加工具，别手改 desc：

```
tavern_card_append { presetId, name: "<卡名>",
  packPath: "D:\\DSH\\dnd-plugin\\contract\\display-blocks-pack.json",
  packVariant: "generic", dryRun: true }   # 先预览，确认后去掉 dryRun
```

> ⚠️ `tavern_card_update` 是**整体替换** desc，拿它追加会把 16K 设定截断 —— 不要用。

**装到别的插件/预设**：直接引 `D:/DSH/display-blocks/lib/{spec,parse}.js`
（纯 ESM、零依赖、无宿主 peer），或把 `contracts.generic` 那段文本加到预设的常驻提示里。

### 换卡 / 换预设之后怎么保证还在（关键）

契约的**载体决定可靠性**。按 dsh-tavern 的 `cardTextFor()`（`lib/index.js:1530-1599`），
每轮**无条件**往 system prompt 拼三样东西：

| 源 | 内容 | 换一张卡之后 |
|---|---|---|
| ① `agent.cordis.yml` | 卡文本（persona prefix） | 跟着卡变 |
| ② `characters.json` | 所有启用卡的 desc / first / text / content | **没了** |
| ③ `presets.json` → `modules[]` | 预设词条 / 模块 | 在，但会被重导 / 面板覆盖 |

**第四种载体最稳：插件 `dsh-block-contract`**（`D:\DSH\block-contract`）——
它是**代码**，挂在 profile 的 bundles 里，自己判断「本会话挂的是不是有角色卡的预设」，
只对角色扮演会话每轮注入：

- 不随角色卡变化（换卡 / 重导卡 / 改 `presets.json` 都不影响）
- 不靠模型自愿（不是 skill 那种"模型可能不读"）
- 编程会话（`liangshen` 等无角色卡的预设）不会多这 635 字

三条载体按需选一条即可，**别叠用**（会注入两遍）：

| 载体 | 换卡 | 换预设 | 装法 |
|---|---|---|---|
| 插件（推荐） | ✅ | ✅（profile 级） | profile 的 bundles + junction，见 `D:\DSH\block-contract\README.md` |
| 预设模块 | ✅ | 要重装 | `apply-as-preset-module.mjs --preset <id>` |
| 卡 desc | ❌ | ❌ | `tavern_card_append` / `dry-run-append.mjs` |

⚠️ **最容易漏的一环：装对了 ≠ 生效。** 世界书 / 卡 / 契约**只对「绑定了该预设的会话」注入**；
0 个会话绑定 = 什么都没生效（表现是"AI 像普通聊天、没有状态卡"）。
`check-last-turn.mjs` 会直接把这件事报出来。

三条只读验证（都在 `D:\DSH\dnd-plugin\contract\`）：

```bash
node verify-injection.mjs <presetId>   # 三条载体一起查：面板视图 / 复现组装 / 插件是否挂上
node check-last-turn.mjs               # 最近一轮模型到底写没写块 + 会话绑定检查
node dry-run-append.mjs                # 往卡 desc 注入的预演（另一条路，先看 token 预算）
```

## 八、常见错误

| 症状 | 原因 |
|---|---|
| 块没渲染，原样显示 JSON | JSON 里有尾逗号 / 单引号 / 中文引号（跨行本插件能读，但别依赖） |
| **整段 JSON 原样显示在对话里** | 插件没装进当前 profile，或装完没重启 —— 查 profile 的 `dsh.profile.bundles` 里有没有 `dsh-display-blocks` |
| 稀有度没上色 | 词不在词表（写了 `（秘宝）` 但卡里没声明 `稀有度: 秘宝=#00e5ff`） |
| 某一节不显示 | 值是空字符串 / 空数组 / 空对象（空节会被丢掉） |
| 颜色没生效 | 色值既不是 `#hex` 也不是词表里的色名 |
| 内容被当成块 | `[[X]]{` 后面跟着的必须是**一行**合法 JSON 对象 |
| 商店/升级块没渲染 | 那五个标记归 DND 皮肤管，要用 `machine-blocks-pack.json` 的契约形状，不要套本契约的 `节` |
