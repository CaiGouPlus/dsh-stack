> **状态**：草案 v1（2026-09-13），**尚未落地**，未改任何项目文件。
> **作用**：定义 `[[商店]]` 与 `[[升级]]` 两个机器块。它们是"AI 生成内容 → 前端渲染 → 玩家交互 → 写回对话"
> 这条链路的**唯一数据契约**，与渲染路线（客户端插件 / 皮肤 hooks）无关 —— 换路线不用改契约。
> **作者约束**：本文件里所有数值**都取自项目既有表**，未新造任何规则。取自既有表的行都标了出处；
> 项目里确实没有的（属性值提升 ASI / 专长获取）按世界书《规则推定协议》补全并**显式标注〔规则推定〕**。

## 0. 先读：与现有机器块的关系（决定实现方式）

现有机器块是 `[[状态更新]]{json}` / `[[状态更正]]{json}`。皮肤侧对它的处理分三步，
新块必须**逐一同族**，否则解析不到：

| 步骤 | 现有实现 | 出处 |
|---|---|---|
| ① 文本增强闸门 | `MARKER` 正则决定"这条消息要不要走增强" | `hooks.mjs:51` |
| ② 逐节点分流 | `enhanceTextNode` 用 `m[0]` 前缀判断是不是**真机器块** | `hooks.mjs:124` / `:202` |
| ③ 包成隐藏节点 | 真机器块打 `data-dnd-machine="1"`，CSS 隐藏但**文本仍可读** | `hooks.mjs:201-204` |

**关键约束（已从源码核实）**：

1. `MARKER`（`:51`）不认 `[[商店]]` → 整条消息**根本不会进入**文本增强。
   必须扩成 `\[\[(?:状态(?:更新|更正)|商店|升级)\]\]`。
2. `enhanceTextNode` 的正则（`:124`）有 **6 个捕获组且组号固定**，源码注释明确写着
   "追加组必须往后排"。→ **不要加捕获组**，改用 `m[0]` 的前缀分流，把 `data-dnd-machine` 的判据
   （`:202`）扩成同族即可。
3. 机器块**必须是节点文本的开头**：判据是 `/^\s*\[\[状态(?:更新|更正)\]\]\s*\{/`。
   → 新块同样**必须独占一行、以 `[[商店]]{` 开头**，前面不能有字。
   （现有解析器专门防过"皮肤自己写的『来源：[[状态更新]] …』说明文字被误当机器块"这个真实 bug。）

**因此两个新块的格式硬约束：**

```
[[商店]]{"…":"一行合法 JSON，不得换行、不得用单引号、不得有尾逗号"}
[[升级]]{"…":"同上"}
```

⚠️ **JSON 里必须用 ASCII 双引号 `"`**，不能用中文引号 `"…"`
（本文件早期草稿就在示例里误用了中文引号，被契约自检脚本当场抓出）。

## 1. `[[商店]]` 机器块

### 1.1 何时输出

只在**玩家能看见商品**时输出，与既有规则耦合、不新增触发条件：

- 玩家**进店/逛摊/看货**（正文已描写店铺或货架）
- 玩家**询问买卖/价格/有什么好货**
- 玩家**要求查看某商人的货**（此时只列该商人主营类目）

**禁止**：玩家没进店时凭空输出商店、把商店当"随身商城"。

### 1.2 字段定义

```json
[[商店]]{
  "名": "铁砧与皮匠",
  "类型": "武器杂货",
  "店主": "矮人铁匠多伦",
  "位置": "博德之门·下城区",
  "货源": "进阶来源",
  "货币": "gp",
  "溢价": "1.0",
  "商品": [
    {
      "名": "长剑",
      "稀有度": "普通",
      "类别": "武器",
      "属性": "攻击+0 伤害1d8 挥砍",
      "特性": "无",
      "价值": "15gp",
      "价": "15",
      "存量": 3,
      "负重": "3磅",
      "熟练": "武器（长剑）",
      "法术": "无",
      "备注": "铁匠自家打的货",
      "鉴定": "已鉴定"
    }
  ],
  "备注": "店主压价狠，稀有货要交涉"
}
```

| 字段 | 必填 | 取值 | 出处 / 约束 |
|---|---|---|---|
| `名` | ✅ | 店铺名 | AI 自拟，需与当前地点/文化相符 |
| `类型` | ○ | `武器杂货`/`护甲`/`药剂`/`杂货`/`法师`/`黑市`/`拍卖` 等 | 影响可售稀有度上限 |
| `店主` | ○ | 人名 | 应已有或即将有 NPC 出场，不得凭空 |
| `位置` | ✅ | `城市·区域` | **必须与 `<状况>` 的「位置」字段一致** |
| `货源` | ✅ | `日常来源`/`进阶来源`/`主线来源`/`高潮来源` | 决定稀有度区间，见 1.3 |
| `货币` | ○ | 默认 `gp` | 与【规则速查-经济与货币】一致 |
| `溢价` | ○ | 默认 `"1.0"` | 非常稀有走黑市时 `1.5~2` |
| `商品[]` | ✅ | ≤12 件 | 与正文/装备卡 11 字段**同构**，便于复用渲染 |
| `备注` | ○ | ≤30 字 | 店主性格/议价钩子 |

**商品项字段**：与既有【装备卡标准模板】的 11 字段**一一对应**
（名称｜稀有度｜类别｜属性｜特性｜价值｜状态｜负重｜熟练｜法术｜备注），
额外加三个商店专用字段：

| 字段 | 含义 | 约束 |
|---|---|---|
| `价` | 实际售价（数字，单位同 `货币`） | 与 `价值` 的关系受来源/溢价约束，见 1.3 |
| `存量` | 可售数量 | 整数；`0` 表示已售罄（前端置灰） |
| `鉴定` | `已鉴定`/`未鉴定` | 未鉴定时 `特性`/`法术` 写 `未知`（沿用既有未鉴定规则） |

### 1.3 价格与货源（**全部取既有表，不得新造**）

| `货源` | 稀有度区间 | 价格依据 | 出处 |
|---|---|---|---|
| `日常来源` | 普通～非普通 | 白板按【常见装备库】基准价；带词条按【装备价值表】 | 生成基准卷 `装备稀有度·来源定档` |
| `进阶来源` | 非普通～稀有 | 同上 | 同上 |
| `主线来源` | 稀有～非常稀有 | 同上 | 同上 |
| `高潮来源` | 非常稀有～传说 | 同上 + 【传奇装备规则】唯一性 | 同上 |

**硬规则（沿用既有条目，逐条有出处）**：

- 价值公式：`价值 = 档位下限 × 词条修正`，`词条修正 = 1 + 0.5×A类词条数 + 1×B类词条数 + 招牌机制额外1`，
  结果**钳制在该档区间内**；档位下限 = 普通10 / 非普通100 / 稀有1,000 / 非常稀有10,000 / 传说100,000。
  → 生成基准卷 `装备价值表`
- **白板豁免**：0 词条的非魔法白板走 5e 基准价（匕首 2gp、长弓 50gp、链甲 75gp…），
  **不套** 10gp 下限。→ `装备价值表`【白板豁免】
- **非常稀有**：仅大都会黑市/法师行会/教会高层有货，溢价 `1.5~2×`，且需交涉/声望检定才肯出手。
  → `装备稀有度概率与获取`【商店规则】
- **传说级商店基本不售**：若出现＝**剧情事件**（拍卖会/失窃案/匿名委托），由世界引擎明确安排并给铺垫，
  **禁止随手上架**。→ 同上
- **卖装备**＝评估价值 × 5~7 成（店主压价），行会/鉴赏家渠道更高。→ `装备价值表`【特例】
- 建卡期（车卡台）**仅展示寻常物品**；魔法物品只在游戏内商店出现。→ 参考站实测 `建卡流程仅展示寻常物品。`

### 1.4 玩家交互 → 写回对话

商店面板只做三件事：**展示、加购、下单**。它**不改任何数值**。

下单时前端生成一句人话并要求 AI 结算，例如：

```
我要买：长剑×1、火把×2，共 21gp。
```

AI 下一轮必须：① 扣除金币 ② 把物品写进 `[[状态更新]] 物品` 分区
③ 更新 `<status>` 物品栏与"状态"字段 ④ 正文给一句成交换取。
→ 交易因此**进入归档链路，可追溯、可读档**，不需要给 `状态归档.cjs` 加任何东西。

## 2. `[[升级]]` 机器块

### 2.1 何时输出

**XP 达门槛的那一轮**。既有契约强制"禁止默默升级"：

> XP 达门槛（300/900/2700/6500/14000…）当轮**立即**按【升级N→N+1】流程升级……
> 禁止默默给经验或默默升级。 —— 规则层 `主线任务系统`

### 2.2 字段定义

```json
[[升级]]{
  "从": 3,
  "到": 4,
  "累计XP": 2900,
  "下一门槛": 6500,
  "职业": "战士",
  "自动": {
    "生命骰": "d10",
    "HP增量": 8,
    "HP上限": "37/37",
    "熟练加值": 2,
    "法术位": {},
    "新特性": ["战斗大师·卓越骰 d8"]
  },
  "待选": [
    { "类": "属性值提升", "选项": ["力量+2", "敏捷+2", "体质+2", "智力+2", "感知+2", "魅力+2", "力量+1且敏捷+1", "…"], "状态": "必选", "推定": true },
    { "类": "专长", "选项": ["（与属性值提升二选一）"], "状态": "可选", "推定": true }
  ],
  "备注": "升级是叙事事件，正文须给一段训练/顿悟"
```

| 字段 | 必填 | 说明 | 出处 |
|---|---|---|---|
| `从` / `到` | ✅ | 等级变化 | 门槛表见下 |
| `累计XP` | ✅ | 当前累计 XP | `<status>` "状态"字段已记 |
| `下一门槛` | ✅ | 下一级门槛 | 门槛表见下 |
| `职业` | ✅ | 用于查生命骰/特性/法术位 | worldbook 职业树 |
| `自动.生命骰` | ✅ | 该职业生命骰 | worldbook 职业细则 |
| `自动.HP增量` | ✅ | **掷生命骰 + 体质修正（或固定平均）** | `规则速查-升级` 第①条 |
| `自动.熟练加值` | ✅ | **仅 5/9/13/17 级变化 → +3/+4/+5/+6** | 同上 第③条 |
| `自动.新特性` | ○ | 按职业获得 | 同上 第④条 |
| `待选[]` | ○ | 需要玩家选的项 | 见 2.3 |
| `推定` | ○ | `true` 表示该项为〔规则推定〕，前端必须显式标注 | 规则推定协议 |

### 2.3 升级门槛表（**照抄既有表，不得改**）

```
2级300 / 3级900 / 4级2700 / 5级6500 / 6级14000 / 7级23000 / 8级34000 / 9级48000
/ 10级64000 / 11级85000 / 12级100000 / 13级120000 / 14级140000 / 15级165000
/ 16级195000 / 17级225000 / 18级265000 / 19级305000 / 20级355000
```
出处：规则层 `规则速查-升级`【升级门槛（累计XP）】

**自动结算四步（逐字照抄）**：
1. HP增量 = 掷生命骰 + 体质修正（或固定平均）
2. 生命骰 +1
3. 5/9/13/17 级：熟练加值 → +3/+4/+5/+6
4. 按职业获子职业/新特性/专长/法术位

**成长曲线硬约束**：禁止一次战斗连升多级、禁止跳级，XP 严格核算。
出处：`规则速查-升级`【成长曲线】

### 2.4 ⚠️ 项目里**缺失**的部分（必须按〔规则推定〕补全）

我逐库检索确认：项目**没有**"属性值提升（Ability Score Improvement）"条款。
`升级N→N+1` 四步里第 1~3 步全自动，**第 4 步只写"按职业获子职业/新特性/专长/法术位"**，
没有规定**谁在什么等级选、选什么**。

因此升级界面里"需要玩家选择"的四项如下，前两项为新增推定：

| 项 | 触发等级 | 内容 | 状态 |
|---|---|---|---|
| **属性值提升** | 4/8/12/16/19 | `+2 一维` 或 `+1/+1 两维`，上限 20 | 🆕 **〔规则推定〕** |
| **专长** | 同上级 | 与属性值提升**二选一** | 🆕 **〔规则推定〕** |
| 子职业 | 战士 2；武僧/游侠 3；其余多数 3 | 见 worldbook 职业细则 L2/L3 | ✅ 已收录 |
| 新法术/戏法 | 施法职业升级 | 准备数 = 等级 + 施法属性；戏法 5/11/17 级 ×2/×3/×4 | ✅ 已收录（`规则详查-融合精要`） |

**推定条款必须遵守《规则推定协议》**（规则层:476）：
① 按 5e 同类规则合理补全 ② **在叙述中标注〔规则推定〕** ③ 不得声称"这是官方原文"
④ 玩家可在【房间规则区】否决或自定义。

→ 前端在升级向导里对这两项**必须显示〔规则推定〕角标**，输出文本也必须带标注。

### 2.5 玩家交互 → 写回对话

升级向导完成后生成一句话，例如：

```
升到4级：属性值提升 力量+2。（〔规则推定〕，若你想改选专长请说）
```

AI 下一轮必须：① 更新 `<status>` 的等级/XP/HP上限/熟练加值 ② 写 `[[状态更新]] 角色` 与 `属性`
③ 正文给一段训练/顿悟叙事。→ 与既有"升级N→N+1"流程完全兼容。

## 6. 装备图标素材清单（对应"装备也要图片素材"）

**技术方案（推荐）**：自绘 SVG，**内联在渲染层里**，用 `currentColor` 描边。

| 理由 | 说明 |
|---|---|
| 规避 CSS 白名单 | 皮肤 CSS 的 `url()` **禁止**远程/绝对/`../`（`check-map-assets.cjs` 第④条），内联 SVG 完全绕开 |
| 自动适配主题 | `currentColor` + 稀有度变量 → 亮/暗、七档色阶全部自动 |
| 零许可负担 | 不引入第三方素材与署名义务 |
| 体积 | 单枚 ~0.5 KB，40 枚约 20 KB |

**图标清单（40 枚）**：

| 组 | 条目 |
|---|---|
| 近战武具（9） | 长剑 / 短剑 / 匕首 / 巨剑 / 手斧 / 战斧 / 战锤 / 巨锤 / 长矛 |
| 远程与长柄（6） | 长弓 / 短弓 / 轻弩 / 重弩 / 长棍 / 戟 |
| 施法器（5） | 法杖 / 魔杖 / 权杖 / 圣徽 / 法器 |
| 护甲与盾（6） | 皮甲 / 镶钉皮甲 / 锁子甲 / 鳞甲 / 板甲 / 盾牌 |
| 杂项装备（5） | 头盔 / 靴子 / 斗篷 / 手套 / 腰带 |
| 饰品（3） | 戒指 / 项链 / 护符 |
| 消耗品（4） | 药水 / 卷轴 / 弹药 / 口粮 |
| 其他（2） | 工具 / 钱袋 |

**兜底规则**：图标按**类别 + 名称关键词**匹配；匹配不到时用「类别通用图标」，
再匹配不到用**首字圆形占位**（沿用项目已有的缺图降级做法）。

**传说/神器级**（可选增强，需你拍板）：用项目已有的豆包出图链路
（`_compat\gen-map-art.cjs` 同款）为**具名传说装备**生成专属插画。
代价是 API 费用与风格一致性风险 —— 因此我建议**先只做 SVG 图标**，传说插画作为 P2 增量。
